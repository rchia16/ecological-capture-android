# Glasses microphone recording

The app checks and requests **DAT `Permission.MICROPHONE` through Meta AI**, separately from Android's phone microphone permission. It configures `StreamConfiguration.audioCodec = AudioCodec.PCM(AudioSampleRate.RATE_16000, 1)` and subscribes to `Stream.audioStream` before starting the camera stream. It uses the DAT glasses microphone stream rather than selecting an Android Bluetooth SCO input. The previous implementation depended on SCO becoming active, which did not occur on the connected Pixel 9.

Only frames received while a clip is armed are saved to private temporary PCM. At finalization `DatAudioRecorder` encodes them to AAC and `AudioVideoMuxer` adds the audio to the existing HEVC MP4 without re-encoding video. The offset is the difference between the first audio `presentationTimeUs` and the first written video frame's DAT timestamp, allowing pre-keyframe audio to be trimmed. Review playback and the existing transfer path use the resulting MP4. PCM and temporary AAC files are removed after finalization. There is no phone microphone fallback.

If permission is denied, no PCM frames arrive, timestamps are invalid, AAC encoding fails, or audio cannot be merged, the original video is retained and the app reports the specific available failure reason. DAT PCM audio is experimental in 1.0.1; Meta currently does not permit publishing apps that use experimental features. See [Meta's audio streaming guide](https://github.com/facebook/meta-wearables-dat-android/blob/main/.cursor/rules/audio-streaming.mdc) and [SDK changelog](https://github.com/facebook/meta-wearables-dat-android/blob/main/CHANGELOG.md).

Verification: 73 JVM tests pass. Five Pixel 9 instrumentation tests pass in a separate benchmark package, using synthetic media: PCM -> AAC -> decoded non-silent samples, timestamp offset/MP4 merging, no-frame cleanup, invalid timestamp rejection, existing AAC/HEVC merging, and preservation of video when audio is missing. No physical glasses microphone samples were captured by those tests. Acceptance requires a new glasses recording after granting the Meta AI microphone permission and checking audible playback in Review Recordings.

The gateway-enabled debug build was then assembled and installed with `adb install -r` as an update to `com.rchia.ecocapture`. The two existing recording files had identical on-device SHA-256 values before and after installation, and the gateway enrolment activity remained enabled.
