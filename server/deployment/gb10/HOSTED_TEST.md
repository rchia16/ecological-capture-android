# Checkpoint 4 live HTTPS synthetic acceptance

The gateway is implemented and hosted; this final technical acceptance exercises the live endpoint, rather than only in-process image tests. All fixtures are approximately 128 KiB of generated MP4-shaped structural bytes plus synthetic event/manifest JSON, not playable video or participant recordings. Transport stays mock; receipts must say mock and not archived. These scripts do not call FileSender, email, change Funnel routes or read SSH/FileSender keys. They intentionally create only temporary synthetic installation credentials/jobs in the gateway's existing development database.

The runner uses standard verified HTTPS, with no HTTP fallback, redirect following, disabled certificate checks, environment proxy or token logging. Run its client phases on Windows with **Tailscale/VPN off** to exercise the public endpoint. An ordinary Wi-Fi internet connection is fine; mobile-only phone reachability was already confirmed separately. Keep the existing gateway/Funnel running except for the deliberate gateway-only restart between pause and resume. Existing 8443 service and Tailscale daemon are untouched.

## 4. Public client: upload then pause

Probe correction after the first attempt: send the full generated 4 MiB + 1 byte oversized chunk, rather than declaring a large Content-Length with no body. An incomplete HTTP body can make an intermediary wait and invalidate the test. Only explicit HTTP 413 counts as successful size rejection; a disconnect/timeout does not. Network failures now include a safe endpoint category (no token, raw path or transfer ID). The two-installation and approximately 128 KiB accepted-fixture scope is unchanged; the extra oversized rejection request contains only generated bytes.

Disable Tailscale only on Windows; leave Tailscale running on GB10, where it hosts Funnel. SSH/SCP to the private 100.76.243.123 address will be unavailable from Windows while its VPN is off, but the public HTTPS client needs no SSH. Re-enable Windows Tailscale when switching back to host administration. Ensure the foreground gateway survives loss of the Windows SSH connection; use a GB10-local terminal or a host-supported persistent terminal session if necessary. For a client failure, first run the credential-free health probe:

```powershell
python -B server/ecocapture_gateway/probe.py https://promaxgb10-4e2b.tail06a565.ts.net/v1/health
```

Expected: `HTTPS_MOCK_GATEWAY_REACHABLE`. The updated hosted runner reports specific safe DNS/network/TLS/local-file codes instead of raw exceptions. No script recopy to GB10 is necessary for a Windows-only diagnostic change.

With Windows Tailscale/VPN **off**, from the repository root:

```powershell
python -B server/deployment/gb10/hosted_probe.py pause --credentials "$probeFolder/credentials.json"
```

Expected status: `HOSTED_UPLOAD_PAUSED`, `accepted_bytes:65536`. This verifies trusted mock health, authenticated idempotent creation, unauthenticated rejection, another installation's read/write/complete/cancel/receipt isolation, identical replay, conflict offset, bad chunk hash rejection, incomplete completion rejection, oversized declared body rejection and traversal rejection. It creates an empty B job for the later independent revocation test. Progress contains only synthetic IDs/offsets, is written mode 0600 outside Git and refuses overwrites. HTTP errors are reported by safe code/status only.


Expected: `HOSTED_RESUME_AND_MOCK_RECEIPT_VERIFIED`. This checks the persisted offset, resumes remaining bytes, verifies the expected manifest hash and mock/not-archived receipt, repeats completion and reads the identical receipt. A separate fully uploaded fixture with an intentionally wrong whole-video hash must fail completion. Only these probe jobs are cancelled, removing their local synthetic payloads. The receipt test proves identical protocol results; local image tests separately established one persisted mock intent per transfer.

This deliberately interrupts between accepted chunks and restarts the server; it does not claim a mid-body network-drop test. If a phase fails, report its safe status/code before rerunning; progress is guarded and the probe is an acceptance script, not the production Android retry worker.
